# 要件 — Giftia 送別ギフトの「決めきれない」を解決する

前提: 今回は Web アプリのモック（PoC）を作る。2026-11-17（火）の週までは手元のパソコンで動かし、その後 Azure にデプロイする予定（N-06、ADR-0009）。元にした書類：班の「要件定義書1115」（2026-11-15 版）の 2章（Phase1）・3章（要求→要件マッピング）・4.1（機能一覧）。
開発①で作るのは、班のワイヤーフレームの ②〜⑤。① 条件を入れる（BR-01）は今の検索画面をそのまま使う（ADR-0008）。ただし、続く ③〜⑤ に進むために、検索結果の商品を「候補に入れる」機能は作る（F-03）。

## 非機能要件

| ID | 要件 | 受入基準 |
| --- | --- | --- |
| N-01 | DB の接続情報は `.env` だけに置き、Git・画面・ログに出さない | `git ls-files` に `.env` がない。画面の JS に接続情報がない |
| N-02 | 班のDBの既存7つの表（`products` など）は変えない。新しい表を足すだけ | 既存の表の列が、開発の前とあとで同じ（`DESCRIBE` で確かめる） |
| N-03 | 受け取った値は SQL の文字列につなげず、`%s` で渡す | コードに `f"...{入力}..."` の形の SQL がない（レビューで見る） |
| N-04 | 共有リストの番号は推測できないものにする（連番にしない） | 番号が UUID（36文字）になっている |
| N-05 | 名前は30文字、コメントは200文字までに制限する | 31文字の名前を送ると保存されず、エラーが出る |
| N-06 | 2026-11-17（火）の週までは手元で動けばよい。その後 Azure にデプロイする予定なので、**デプロイで変わるもの（API の URL、画面の URL、CORS の許可先、DB の接続情報）はコードに直接書かず、環境変数か、開いているページから取る**（ADR-0009） | 今週：`npm run dev` と `uvicorn main:app --reload` で通しで動く。来週：コードに `localhost` を直接書いた箇所がない（`lib/api.ts` 26行目の初期値は除く） |
