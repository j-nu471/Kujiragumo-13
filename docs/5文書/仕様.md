# 仕様 — Giftia 送別ギフトの「決めきれない」を解決する

前提: モック。2026-11-17（火）の週までは手元のパソコンで動かす（画面は Next.js の http://localhost:3000、API は FastAPI の http://localhost:8000）。その後 Azure にデプロイする予定（ADR-0009）なので、下の URL の `localhost` の部分はデプロイ先で変わる。DB は班の Azure Database for MySQL（開発用）。ログインはない。

## 全体像

贈る人が候補を3つまで選んで共有リストを作り、URL を同僚に送る。同僚はその URL を開いてアンケートに答え、候補に賛成・コメントする。贈る人は集まった声を見て、1つの商品の購入ボタンを押す。

```
贈る人 ①検索 → ②候補を選ぶ → ③共有URLを作る ──(LINE などで人が送る)──▶ 同僚 ④答えて賛成する
贈る人 ⑤集まった声を見て、購入ボタンを押す ◀── DB に保存された賛成・コメント・アンケート
```

①〜⑤は、班のワイヤーフレームの画面の番号。

## 画面・操作
<!-- 画面ごとに ### で分ける -->

### ① 条件を入れる（贈る人）— F-01（開発①では変えない）
- 今ある検索画面（`/`）をそのまま使う。入力欄・検索 API には手を入れない（ADR-0008）

### ② 候補を選ぶ（贈る人）— F-03
- 今の検索結果の表示（人気順の上位20件）はそのまま
- 足すのは、商品ごとの「候補に入れる」のチェックだけ。3つまで選べる。4つ目は選べない
- 画面の下に「候補 ◯/3」と「共有リストを作る」ボタン（1つ以上選ぶと押せる）
- 全件数・次の20件・「評価なし」の表示（F-02）は開発①では作らない

### ③ 共有URLを送る（贈る人）— F-03
- パス：`/s/{share_id}/created`
- 選んだ候補3つ、共有URL、コピーボタン、同僚に送る文の例を出す
- 共有URLは「今開いているページのアドレスの頭（`window.location.origin`）＋ `/s/{share_id}`」で作る。`localhost` を直接書かない（デプロイ後もそのまま使えるように。N-06）
- 「集まった声を見る」で⑤へ

### ④ 答えて賛成する（同僚）— F-04・F-05
- パス：`/s/{share_id}`（共有URL）
- 名前の入力欄
- アンケート3問。答えは「はい／いいえ／分からない」
- 候補ごとに「賛成する」ボタンとコメント欄
- 「送る」ボタンでまとめて保存する

### ⑤ 集まった声を見て買う（贈る人）— F-06・F-07（・F-08）
- パス：`/s/{share_id}/summary`
- 回答した人数と名前、候補ごとの賛成数・賛成した人・コメント、アンケートの答えの集計
- 賛成数がいちばん多い商品に「この商品を買う」ボタン。押すと記録し、「記録しました」と出す（今のアプリには商品ページがないため、開かない）
- F-08 ができたら、1位と選ばれた理由の枠を出す

## 入力と出力

| 要件ID | 入力 | 処理 | 出力 |
| --- | --- | --- | --- |
| F-01（変えない） | `GET /api/search`（今のまま） | 今のまま | 今のまま。`results` の `id` を「候補に入れる」で使う |
| F-03 | `POST /api/shares` 本文 `{"product_ids": ["G0001", …]}`（1〜3個） | 共有リストを作り、候補を順番つきで保存する | `{"share_id": "UUID"}` |
| F-04・F-05 | `GET /api/shares/{share_id}` | 共有リストの候補を取る | `{"share_id", "items": [{"id","name","price","rating"}]}` |
| F-04・F-05 | `POST /api/shares/{share_id}/answers` 本文 `{"voter_name": "Bさん", "survey": [{"question_key": "scent", "answer": "yes"}, …], "votes": ["G0001"], "comments": [{"product_id": "G0001", "body": "先輩っぽい"}]}` | アンケート・賛成・コメントをまとめて保存する。同じ人の同じ商品への賛成は1回だけ | `{"ok": true}` |
| F-06 | `GET /api/shares/{share_id}/summary` | 賛成数・コメント・アンケートを集計する | `{"respondents": ["Bさん", …], "items": [{"id","name","price","votes": 3,"voters": [...],"comments": [{"voter_name","body"}]}], "survey": {"scent": {"yes":2,"no":0,"unknown":0}, …}}`（`items` は賛成数の多い順） |
| F-07 | `POST /api/shares/{share_id}/purchase-click` 本文 `{"product_id": "G0001"}` | 購入ボタンを押した記録を残す | `{"ok": true}` |

## データ
<!-- テーブル定義・保存先の方針 -->

既存の7つの表（`products`・`product_scenes`・`orders`・`order_items`・`reviews`・`users`・`product_facts`）は変えない（N-02、ADR-0005）。次の6つの表を新しく作る。

| 表 | 列 | 説明 |
| --- | --- | --- |
| `share_lists` | `share_id` VARCHAR(36) 主キー、`created_at` DATETIME | 共有リスト1つにつき1行。番号は UUID（ADR-0007） |
| `share_items` | `share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`position` TINYINT（1〜3）。主キー（`share_id`, `product_id`） | 共有リストに入れた候補 |
| `votes` | `share_id`、`product_id`、`voter_name` VARCHAR(30)、`created_at`。主キー（`share_id`, `product_id`, `voter_name`） | 賛成。同じ人が同じ商品に2回賛成できない |
| `comments` | `comment_id` INT 自動の番号 主キー、`share_id`、`product_id`、`voter_name` VARCHAR(30)、`body` VARCHAR(200)、`created_at` | コメント |
| `survey_answers` | `share_id`、`voter_name` VARCHAR(30)、`question_key` VARCHAR(30)、`answer` VARCHAR(10)、`created_at`。主キー（`share_id`, `voter_name`, `question_key`） | アンケートの答え。`question_key` は `scent`・`sweets`・`coffee`、`answer` は `yes`・`no`・`unknown` |
| `purchase_clicks` | `click_id` INT 自動の番号 主キー、`share_id`、`product_id`、`clicked_at` DATETIME | 購入ボタンを押した記録（F-07） |

作る SQL は `backend/sql/001_share_tables.sql`（設計.md）。

## エラー時の挙動

| 場面 | API の返し方 | 画面の出し方 |
| --- | --- | --- |
| 存在しない `share_id` | 404 | 「この共有リストは見つかりません」 |
| 候補が0個、または4個以上 | 400 | ボタンを押せないようにしておく |
| 名前が空、名前が31文字以上、コメントが201文字以上 | 400 | 入力欄の下に理由を出す |
| アンケートの答えが `yes`・`no`・`unknown` 以外 | 400 | 選択肢でしか選べないようにしておく |
| 同じ人が同じ商品にもう一度賛成 | 200（保存はしない） | 賛成数は増えない |
| DB につながらない | 500（接続情報やエラーの全文は返さない） | 「時間をおいてもう一度お試しください」 |
