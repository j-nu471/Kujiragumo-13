# 仕様 — Giftia 送別ギフトの「決めきれない」を解決する

前提: モック。2026-11-17（火）の週までは手元のパソコンで動かす（画面は Next.js の http://localhost:3000、API は FastAPI の http://localhost:8000）。その後 Azure にデプロイする予定（ADR-0009）なので、下の URL の `localhost` の部分はデプロイ先で変わる。DB は班の Azure Database for MySQL（開発用）。ログインはない。

## 全体像

贈る人が候補を3つまで選んで共有リストを作り、URL を同僚に送る。同僚はその URL を開き、名前を入れずに（匿名）候補の1つに賛成し、候補ごとに「いいと思った理由」とひとことを送る。贈る人は集まった声を見て、1つの商品の購入ボタンを押す。

```
贈る人 ①検索 → ②候補を選ぶ → ③共有URLを作る ──(LINE などで人が送る)──▶ 同僚 ④答えて賛成する
贈る人 ⑤集まった声を見て、購入ボタンを押す ◀── DB に保存された賛成・コメント
```

①〜⑤は、班のワイヤーフレームの画面の番号。

## 画面・操作
<!-- 画面ごとに ### で分ける -->

### ① 条件を入れる（贈る人）— F-01（開発①では変えない）
- 今ある検索画面（`/`）をそのまま使う。入力欄・検索 API には手を入れない（ADR-0008）

### ② 候補を選ぶ（贈る人）— F-03
- 今の検索結果の表示（人気順の上位20件）はそのまま
- 足すのは、商品ごとの「候補に入れる」のチェックだけ。3つまで選べる。4つ目は選べない
- 画面の下に「候補 ◯/3」と「共有リストを作る」ボタン（1つ以上選ぶと押せる）
- 全件数・次の20件・「評価なし」の表示（F-02）は開発①では作らない

### ③ 共有URLを送る（贈る人）— F-03
- パス：`/s/{share_id}/created`
- 選んだ候補3つ、共有URL、コピーボタン、同僚に送る文の例を出す
- 共有URLは「今開いているページのアドレスの頭（`window.location.origin`）＋ `/s/{share_id}`」で作る。`localhost` を直接書かない（デプロイ後もそのまま使えるように。N-06）
- 「集まった声を見る」で⑤へ

### ④ 賛成・コメント（同僚）— F-04
- パス：`/s/{share_id}`（共有URL）
- 名前の入力欄はない（匿名。ADR-0010）。「匿名で回答します。名前は入れません」と出す
- 候補3つ（商品名・価格・評価）を出す
- 候補ごとに「賛成」ボタン。**賛成できるのは3つの中から1つだけ**。別の候補を押すと賛成が移る
- 候補ごとに、コメントとして「いいと思った理由」を1つ選べる（任意）：「送る人にあってる」「おいしそう」「自分も欲しい」。賛成していない候補にも付けられる
- 候補ごとに、ひとこと（自由記述・200文字まで・任意）
- 「送る」ボタンでまとめて保存する。送ったあとは「ありがとうございました」と出し、送るボタンを押せなくする（同じ人を見分けないため。ADR-0010）

### ⑤ 集まった声を見て買う（贈る人）— F-06・F-07（・F-08）
- パス：`/s/{share_id}/summary`
- 回答した人数（匿名。名前は出さない）
- 候補を賛成の多い順に並べる（並べ方は F-08 と同じ。ADR-0011）。候補ごとに、賛成数、「いいと思った理由」ごとの人数（例：送る人にあってる 2人／おいしそう 1人）、ひとことの一覧
- 候補ごとに「この商品を買う」ボタン。押すと記録し、「記録しました」と出す（今のアプリには商品ページがないため、開かない。決済はしない）
- F-08 ができたら、いちばん上に1位と理由の枠を出す：「1位：商品名」「3人が賛成。いいと思った理由：送る人にあってる（2人）」。賛成が全部0なら出さず、「まだ1件も賛成がありません」と出す

## 入力と出力

| 要件ID | 入力 | 処理 | 出力 |
| --- | --- | --- | --- |
| F-01（変えない） | `GET /api/search`（今のまま） | 今のまま | 今のまま。`results` の `id` を「候補に入れる」で使う |
| F-03 | `POST /api/shares` 本文 `{"product_ids": ["G0001", …]}`（1〜3個） | 共有リストを作り、候補を順番つきで保存する | `{"share_id": "UUID"}` |
| F-04・F-06 | `GET /api/shares/{share_id}` | 共有リストの候補を取る | `{"share_id", "items": [{"id","name","price","rating","position"}]}` |
| F-04 | `POST /api/shares/{share_id}/answers` 本文 `{"vote": "G0001", "comments": [{"product_id": "G0001", "reason_key": "fits", "body": "先輩っぽい"}]}`。`vote` は賛成した商品の ID 1つ（賛成しないなら `null`）。`reason_key` と `body` はどちらも省略できる | API がランダムな回答番号（`answer_id`、UUID）を1つ作り、賛成とコメントをその番号つきでまとめて保存する。名前は受け取らない | `{"ok": true}` |
| F-06・F-08 | `GET /api/shares/{share_id}/summary` | 回答した人数、候補ごとの賛成数・理由の数・ひとことを集計し、F-08 の順に並べる | `{"respondents": 4, "items": [{"id","name","price","votes": 3,"reasons": {"fits": 2, "tasty": 1, "want": 0},"comments": ["先輩っぽい", …]}], "top": {"id", "name", "votes": 3, "reason_key": "fits", "reason_count": 2}}`（`items` は F-08 の順。賛成が全部0なら `top` は `null`）。`respondents` は `votes` と `comments` に出てくる `answer_id` の種類の数 |
| F-07 | `POST /api/shares/{share_id}/purchase-click` 本文 `{"product_id": "G0001"}` | 購入ボタンを押した記録を残す | `{"ok": true}` |

## データ
<!-- テーブル定義・保存先の方針 -->

既存の7つの表（`products`・`product_scenes`・`orders`・`order_items`・`reviews`・`users`・`product_facts`）は変えない（N-02、ADR-0005）。次の5つの表を新しく作る（ADR-0010）。名前を入れる列は作らない。ER図は要件定義書 5.1。

| 表 | 列 | 説明 |
| --- | --- | --- |
| `share_lists` | `share_id` VARCHAR(36) 主キー、`created_at` DATETIME | 共有リスト1つにつき1行。番号は UUID（ADR-0007） |
| `share_items` | `share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`position` TINYINT（1〜3）。主キー（`share_id`, `product_id`） | 共有リストに入れた候補 |
| `votes` | `vote_id` INT 自動の番号 主キー、`share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`answer_id` VARCHAR(36)、`voted_at` DATETIME | 賛成。1回の回答（`answer_id`）につき1行まで。同じ人かどうかは見分けない（ADR-0010） |
| `comments` | `comment_id` INT 自動の番号 主キー、`share_id` VARCHAR(36)、`product_id` VARCHAR(10)、`answer_id` VARCHAR(36)、`reason_key` VARCHAR(30)（空を許す）、`body` VARCHAR(200)（空を許す）、`created_at` DATETIME | コメント。`reason_key` は `fits`（送る人にあってる）・`tasty`（おいしそう）・`want`（自分も欲しい）。`reason_key` も `body` も空なら保存しない |
| `purchase_clicks` | `click_id` INT 自動の番号 主キー、`share_id`、`product_id`、`clicked_at` DATETIME | 購入ボタンを押した記録（F-07） |

作る SQL は `backend/sql/001_share_tables.sql`（設計.md）。

## エラー時の挙動

| 場面 | API の返し方 | 画面の出し方 |
| --- | --- | --- |
| 存在しない `share_id` | 404 | 「この共有リストは見つかりません」 |
| 候補が0個、または4個以上 | 400 | ボタンを押せないようにしておく |
| POST /api/shares で、products にない商品 ID がある | 400 | 検索結果からしか選べないようにしておく |
| ひとことが201文字以上 | 400 | 入力欄の下に理由を出す |
| `reason_key` が `fits`・`tasty`・`want` 以外 | 400 | 選択肢でしか選べないようにしておく |
| `vote` やコメントの `product_id` が、その共有リストの候補にない | 400 | 候補の中からしか選べないようにしておく |
| 同じ候補へのコメントが2つ以上 | 400「1つの候補に付けられるコメントは1つまでです」 | 候補ごとに入力欄を1組だけにしておく（画面からは起きない） |
| 賛成もコメントも空のまま送る | 400 | 「賛成か理由を1つ以上選んでください」と出す |
| DB につながらない | 500（接続情報やエラーの全文は返さない） | 「時間をおいてもう一度お試しください」 |
